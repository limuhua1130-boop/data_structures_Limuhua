# task3：基于磁盘的外部排序大纲

每次读一小批整数，排序后写成有序小文件，再两两归并，直到只剩一个结果文件

### 文件

- `generate_data.c`：独立的随机数生成器，包含自己的 `main`，生成 `input.txt`
- `sorter.h`：结构、常量、函数声明
- `sorter.c`：分块排序、文件归并
- `main.c`：排序测试

生成器单独编译运行，先生成输入文件，再运行排序程序；不要把 `generate_data.c` 和排序程序的 `main.c` 一起编译，因为两者都有 `main` 函数

### 排序设置

- `Data_num`：输入整数总数，先设为 20
- `Memory_cap`：排序数组容量，先设为 5
- `Min_value`、`Max_value`：随机整数范围，先设为 0～99
- `Seed`：随机种子，固定后方便重复测试
- `input.txt`：原始数据文件
- `output.txt`：最终排序结果文件

文件采用文本格式，每行保存一个整数，通过 `fscanf`、`fprintf` 读写；可以直接打开 txt 查看内容，也可以用 `display_file` 显示

### State：排序状态

| 成员 | 作用 |
| --- | --- |
| `data` | 当前批次的整数数组 |
| `len` | 当前批次实际读到的整数数量 |
| `capacity` | 数组容量，初始为 5 |
| `run_count` | 当前还剩多少个有序小文件 |
| `passes` | 已完成的归并趟数 |
| `comparisons` | 排序和归并时比较整数的次数 |
| `read_values` | 排序过程中从文件成功读取的整数总数 |
| `written_values` | 排序过程中向文件成功写入的整数总数 |

有序小文件也叫“顺串”。临时文件按“趟数、编号”命名，例如 `run_0_0.txt`、`run_0_1.txt`，便于查找和清理

### sorter.c 里的函数

| 函数 | 作用 |
| --- | --- |
| `state_init` | 分配排序数组、统计归零 |
| `state_clear` | 释放数组、将指针置空 |
| `display_file` | 逐个读取整数并显示 |
| `read_block` | 每次最多读取 `capacity` 个整数，记录实际数量 |
| `sort_block` | 对当前批次做插入排序，统计比较次数 |
| `write_run` | 将当前有序数组写成一个顺串 |
| `make_runs` | 重复读取、排序、写出，生成初始顺串 |
| `merge_two` | 将两个有序文件归并成一个有序文件 |
| `merge_runs` | 每趟两两归并，直到只剩一个顺串 |
| `check_result` | 检查结果是否非递减、整数数量是否正确 |
| `cleanup_runs` | 删除本次排序产生的临时文件 |
| `func` | 串起整个外部排序流程 |

`read_block` 要区分“读到一批数据”“正常结束”和“读取失败”；最后一批不足 5 个时，只对实际读到的数排序

`fscanf(fp, "%d", &value)` 返回 `1` 才表示成功读到一个整数；遇到非法文本要报错，不能当成正常文件结束

### merge_two 里的标记

| 变量 | 记什么 |
| --- | --- |
| `left`、`right` | 左右两个输入文件 |
| `out` | 归并输出文件 |
| `a`、`b` | 左右文件当前待比较的整数 |
| `has_a`、`has_b` | 左右文件是否还有待处理的整数 |

先从两个文件各读一个数。比较 `a` 和 `b`，把较小的写入 `out`，只从取走数字的那个文件再读一个数

两个数相等时先取左边的数，右边的数继续保留；一边读完后，把另一边剩下的数逐个写出

### 大致流程

1. 先运行独立的随机数生成器，生成含 20 个整数的输入文件
2. `state_init`：准备容量为 5 的数组
3. `make_runs`：每次读取最多 5 个数，排序并写出，得到 4 个顺串
4. 释放排序数组，保留统计信息；归并阶段只需要左右文件各一个当前数
5. `merge_runs` 第一趟：4 个顺串两两合并，得到 2 个顺串
6. `merge_runs` 第二趟：2 个顺串合并，得到 1 个顺串
7. 将最后一个顺串保存为 `output.txt`
8. `check_result`：检查结果的顺序和数量
9. 输出比较次数、读写量和耗时，清理临时文件及内存

某趟的顺串数量为奇数时，最后一个顺串直接进入下一趟；空输入生成空结果文件

文件打开、读写或内存分配失败时，关闭已打开的文件，释放内存，清理本次临时文件，并返回错误

### 性能记录

- 块内采用插入排序：单块最坏时间为 `O(M²)`，全部初始顺串生成最坏为 `O(NM)`
- 初始顺串数为 `R = ceil(N / M)`；二路归并需要 `ceil(log₂R)` 趟，`R <= 1` 时不需要归并
- 每一趟归并的处理量为 `O(N)`，数据缓冲空间受 `M` 限制
- 先以“传输一个整数”为一个逻辑 I/O 单位，分别累计读取量、写入量；这些数值不等同于真实磁盘访问次数
- 当前 20 个数的例子：顺串生成读写各 20 个，两趟归并分别读写各 20 个，合计读 60 个、写 60 个
- 随机生成、显示和结果检查的读写不计入排序统计；排序耗时覆盖顺串生成和归并

### main.c 里的测试

| 函数 | 作用 |
| --- | --- |
| `test_generate` | 生成 20 个数，检查数量、范围和固定种子的可重复性 |
| `test_block` | 读取 5 个数，检查块内排序结果 |
| `test_runs` | 检查 20 个数是否生成 4 个有序顺串 |
| `test_merge` | 用两个已知有序文件，检查归并结果 |
| `test_sort` | 完整外排，与预先写好的期望结果逐项对照，确认没有丢失或增加数据 |
| `test_boundary` | 测试空文件、单个数、不足一批、尾批不足、奇数个顺串、重复值和负数 |
| `test_error` | 测试文件不存在、格式不完整、非法容量及写入失败后的清理 |
| `main` | 挨个运行测试 |

### 建议实现顺序

1. 数据生成和显示
2. 单批读取与块内排序
3. 初始顺串生成
4. 两个文件的归并
5. 多趟归并与整体调用
6. 结果验证、统计和错误处理
